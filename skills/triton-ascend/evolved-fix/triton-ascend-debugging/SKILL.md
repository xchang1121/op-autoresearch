# Triton Ascend debugging and checking list

> Ben Skill is used only for post-failure diagnostic and repair advice and is not injected into KernelGen as an initial generation constraint.
> If the conclusion is a rule "must be complied with at the time of generation", it should be returned to the fundamental or the corresponding guide.

## Full debug list

### Memory access issues
- [ ] `tl.load`/ `tl.store` for tail block do all `mask` or `boundary_check`?
- [ ] If the error position of the verifier is concentrated at the end of the last dimension, first suspect that tail mask / baseary_check is missing.
- [ ] Does the stride parameter match the `tensor.stride()` entered in the wrapper?
- [ ] If Kernel uses one-dimensional `ptr + offsets`, does it start with `.contiguous()`?

### Control flow check
- [ ] Did you miss /break/continue?
- [ ] Do complex conditions result in `tl.where` / mark too deep a combination?
- [ ] Are `tl.constexpr` used only for kernel parameters?

### Grid and Block Configuration Check
- [ ] Grid, does the total size not exceed 65535?
- [ ] For large sape operator, is a staggered cycle `for i in range(pid, total, core_num)` used?
- [ ] Are Grid dimensions of a tuple type and not exceeding 3 D?

### Conjunctive with Atomic Operations Inspection
- [ ] Did you use atomic operations (`tl.atomic_add`, etc.) for co-writing?
- [ ] Is atomic operation necessary (is it avoidable)?

### Slice & Index Check
- [ ] Did Python-style direct slices (e.g. `b[0]`, `b[i:j]`) be avoided?
- [ ] Did `tl.get_element` be misused for tensor generated by `tl.arange`?
- [ ] Did you do `[0]` Index results for `tl.sum` / `tl.max` and so on?
- [ ] Did the slice operation use the correct API (`tl.get_element`, `tl.extract_slice`, etc.)?

### Performance optimization check
- [ ] Is memory access continuous (avoiding step-by-step visits)?
- [ ] Did you make full use of the parallels in the block?
- [ ] Does the complex operator consider breaking down into more than one simple kernel?

## Common Error Spacing

### Compiler error

| Error Type | Typical symptoms. | Common causes | Solutions |
|---------|---------|---------|---------|
| UB/CBUF Spill | `ub overflow, requires X bits while 1572864 bits available` | BLONK is too big or too many intermediate variables | downsizing BLONK dimensions; reducing the number of tensors active simultaneously |
| HiVM vsel error | `hivm.hir.vsel: Unsupported op for finding the root alloc` | Embedded Mask + tl.where too complex | Replace tl.where: `a * mask.to(dtype)` with multiplication |
| Memory cross-border visits | runtime error, abnormal result, random crash | load/store missing mask or baseary_check | Add the correct mark or baseary_check protection |
| Grid's beyond the limit. | Failed to compile or runtime error | Grid's total size is more than 65535 | Use staggered cycle `for i in range(pid, total, core_num)` or continuous segment processing |
| Control flow error | `unsupported AST node type: Continue` | Use return/break/continue | Change to f-else package logic |
|   while cycle error   | Compiled failed (Asendbackend) | Use the wire loop. | Replace by for + if: `for i in range(MAX): if i < n:` |
| Constexpr index | `ValueError('unsupported tensor index: constexpr[0]')` | Index `[0]` for returned scalar for tl.sum etc. | Directly use scalar results, do not index |
| Slice Syntax Error | Compiled failed | Using `b[0]` or `b[i:j]` direct slices | Use `tl.get_element` or `tl.extract_slice` |
| tl.arange index error | Compiled failed | Use `get_element` for results of `tl.arange` | Directly calculate index values instead of extracting them |
| Type conversion error | `cast incompatible` | Invisible Cast or `tl.float16(scalar)` | Specify acc dtype with `.to(tl.float16)` or visible |
| Misused constexxpr | Compiled failed | Use tl.constexpr on hostside | Use tl.constexpr only for kernel parameters |
| Stride set error | Calculating result error, data error | Errors in calculation or transmission of stide parameters | Validate stride settings, checktensor.stride() |
| Values are unstable | Result is NAN or Inf | Softmax/sqrt, etc. | Minus maximum, check non-negative, use float32 |
| Data competition | I don't know. It's different every time. | Multiprogram and write to the same location | Use tl.atomic_add etc. |
| BLONK_SIZE is too big. | Failed to compile or runtime error | BLONK_SIZE exceeds 65536 or hardware restrictions | Reduce BLONK_SIZE, use recycling |
| tl.where offset calculation | Compiled failed (Asendbackend) | Use tl.where for memory offsets | Change to if-else static branch |
| Low performance. | Run slow | Inconsistent memory access and unreasonable splits | Optimizing memory layout, adjusting BLONK_SIZE, using block_ptr |
| runtimerange border collapse | bishengIR crash | Start/stop of range() mix runtime Variables and constexpr | Change to full constexpr's range (0, N, BLONK_K), skipping in circulation with runtimeif |

### Validation failed to locate

| Error Location Distribution | Preferably suspect. | Remedial direction |
|-------------|---------|---------|
| Focus only on the last dimension, for example, `dim2: [16:17]` | Tiil Mask / `boundary_check` | Check last dimension load/store mask, block_ptr plus `boundary_check=(0, 1)` |
| Error in a whole line or column | Row infoset, stride, switch or `sub_vec_id` offset Error | Review multidimensional index decomposition and block_ptr `shape/strides/offsets/order` |
| All files are like the last ones. | A5 Punctuation Single Buffer covered | cube, wait vector, set buffer-free after reading |
| error with K is significantly larger | fp16 Long chain plus accuracy loss | fp32accumulator; consult Kahan precision six |
